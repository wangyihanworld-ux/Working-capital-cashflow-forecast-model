# 预计回款、实际到账与结算情景

## 决策问题与口径

比较相同应收金额、付款计划、期初现金和最低现金门槛下，不同结算安排是否减少资金缺口。评价采用每日收盘可用现金：最大缺口、缺口天数、最长连续缺口天数、累计缺口金额×天、期末现金，以及费用、价格偏离和期末未变现面值。累计缺口金额×天不等于借款本金，也不是融资利息。

链上收到代币不等于银行账户已有可用于经营付款的现金。本模型计入转账、兑换、赎回等待时间，并对赎回资格、开放日期、最低金额和每日总额度作情景约束。所有参数都是用户提供的假设，并非任何具体稳定币、银行或发行方的产品承诺。

## 输入接口

金额统一用同一种报告币种的百万元，日期使用 `YYYY-MM-DD`。不要混用元与百万元，或未经换算的不同币种。

|文件|字段|定义|
|---|---|---|
|invoices.csv|invoice_id, expected_date, amount_mn|唯一匿名应收标识、预计付款方释放资金日期、应收面值；不是链上到账日期|
|actuals.csv|receipt_id, invoice_id, actual_date, applied_mn, cash_mn|唯一回款标识、关联应收、现金实际可用日、核销面值、实际净现金|
|outflows.csv|date, amount_mn|逐日经营付款计划或已发生付款；可同日多笔|
|terms.json|SettlementTerms 参数列表|首项为比较基准，后续为对照方案|

若原系统的“预计到账日”已经是最终可用现金日，基准安排的额外延迟应设为 0，避免重复加上银行结算时间。新安排的时间需先统一到同一个起点。

`opening_cash_mn` 是分析起始日前一日收盘现金。开始日之前的实际回款只核销应收，不再计入本期现金。截止日 `as_of` 之后的实际记录直接报错，不允许未来信息混入。部分到账仅核销 `applied_mn`，未付余额才进入情景预测；实际净现金不再套用假设手续费。两者差额单列在 `actual_audit`，不武断地全部认定为手续费。重复回款、未知应收、超额核销和非有限金额均被拒绝。

逾期未收金额不会回填进过去现金，而是假设最早在截止日次日由付款方释放；这是需要人工复核的乐观下限，可用新的预计日期或延迟参数施压。当前版本不自动从少量实际记录估计违约率、拖欠分布或回款概率。

## 结算参数

|参数|含义|
|---|---|
|collection_shift_days|付款方相对预计日提前或推迟付款的日数；必须有合同或行为依据，不能解释成链路提速|
|transfer_days / conversion_days / redemption_days|转账、兑换、赎回串行等待的日历天数|
|price_factor|面值转为报告币种的总价格系数，如 0.95 表示折价 5%；可包含显式假设的汇率影响|
|fee_rate / fixed_fee_mn|按变现总额计提的费率，以及每笔未付应收批次的固定费用|
|redemption_allowed|是否具有赎回资格；不满足时整个预测余额无法变现|
|redemption_open_date|最早允许启动赎回的日期，随后仍需等待 redemption_days|
|minimum_redemption_mn|按每笔未付面值判断最低赎回门槛，不跨应收合并|
|daily_capacity_mn|整个情景共享的每日可处理面值额度；按就绪日、应收标识排序分配，0 表示无法变现|

预计净现金 = 剩余面值 × price_factor × (1 − fee_rate) − fixed_fee_mn。

容量拆分时按比例分摊该批次的价格损益和费用；固定费用不是每日重复收取。费用大于变现总额时拒绝输入。链上预付 gas、额外融资成本等应单列付款，本接口未自动推算。当前只按最终可用现金事件计算净额；不代表完整的代币持仓、应收核销和会计损益分录。

## 运行与现有月度模型衔接

```powershell
python -m working_capital.demo
python -m working_capital.settlement_demo --output-dir demo_output/settlement
```

标准 Demo 同时生成结算对比 CSV，包括输入模板、每日现金、月度汇总、逐笔变现记录和实际到账偏差。示例数据全部合成，无真实客户和银行资料。

`forecast_schedule(build_forecast(...))` 将原月度模型的客户回款转换为合成回款批次，将供应商付款与经营费用转换为付款计划。适配器明确假设月末发生，基准无额外延迟时逐月现金与原模型完全勾稽。结算模块从期初现金重新滚动，替换客户回款，不叠加原经营现金流。它不更改原 DSO 应收账本和利润现金桥，不把代币持仓误记为应收；真实分析应提供实际日期明细。Demo 的 `model_overlay_*.csv` 展示这条连接。

使用本地 CSV 输入：

```powershell
python -m working_capital.settlement_demo --input-dir private/settlement --output-dir demo_output/private-settlement --start 2027-01-01 --end 2027-01-31 --as-of 2027-01-08 --opening-cash 10 --minimum-cash 5
```

将模板复制到被 Git 忽略的 `private/settlement/` 后再填入匿名化记录。真实数据及其输出应保持本地；不要放进 `docs/evidence/`。实际流水建议在本地先清除姓名、账号和联系方式，只保留必要字段。

## 结果边界

- 每日模型能识别月末余额掩盖的月内缺口，但无法识别同日内付款先后造成的盘中缺口。
- 采用日历天，不自动处理节假日、截止时间、KYC 审查、网络故障、交易对深度或发行方违约。可通过延迟、价格、额度和不可赎回情景施压；不能认为风险已穷尽。
- 月度适配器没有真实发票或付款日期，其逐日结果只是明确标注的时点假设。
- 实际记录需在现金可用时录入；仅有链上交易哈希不能登记为实际现金。
- 合成情景只能说明模型机制，不能证明稳定币或某家服务商一定降低真实资金缺口。
